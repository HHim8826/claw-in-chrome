# Upstream 1.0.94 feature recovery execution plan

This plan implements the
[upstream 1.0.94 recovery specification](../../product-specs/upstream-1.0.94-recovery.md)
as test-driven semantic ports.

## Goal

Recover the accepted provider-independent 1.0.94 behavior without regressing
Claw in Chrome's current behavior, readable recovery architecture, security
controls, or release packaging.

## Constraints

- Treat the supplied 1.0.94 package as read-only source evidence.
- Don't copy the source package, replace generated bundles, or change manifest
  permissions or the content security policy.
- Write one focused failing test before each implementation slice.
- Prefer readable modules; add a semantic anchor test and a recovery-model
  note for every generated bundle patch.
- Keep each slice independently revertible and commit coherent GREEN
  checkpoints on `feat/upstream-1.0.94`.
- Run `npm run validate:fast` before each checkpoint and
  `npm run validate:full` for the final result.

## Baseline and approval gate

Planning started on `main` at `2ba7c16` with a clean working tree. The user
approved the scope, the enabled-by-default batch setting with an options
toggle, truncated oversized `read_page` output, per-slice commits, a final
version change to `1.0.94`, and automatic push.

## Execution slices

1. Behavior matrix: record source identity, accepted groups, owners, and test
   targets in `scripts/upstream-1.0.94-matrix.js`.
2. `read_page` hardening in the accessibility-tree content script.
3. `javascript_tool` REPL semantics and internal-page rejection.
4. `computer` screenshot scale, page-zoom shortcut rejection, and `type`
   validation.
5. Mid-call blocked-navigation detection and managed-policy wording.
6. Foreign-extension debugger interference recovery.
7. Minimized-window click guard.
8. Phantom cursor, trusted stop clicks, and stop-delivery feedback.
9. GIF mixed-size frame padding.
10. `browser_batch` runtime, registration, result conversion, progress UI, and
    options toggle.
11. Tool activity labels in side-panel tool rows.
12. External-link safety warnings.
13. Markdown local-time hint, excluded after inspection because the source
    never renders it.
14. Version `1.0.94.0`, documentation, full validation, runtime inspection,
    and push.

## Progress evidence

- Baseline: `npm run validate:fast` passed with 66 unit and integration test
  files before any change.
- Slice 2 RED: `node tests/unit/accessibility-tree-hardening.test.js` failed
  because a payment-card value appeared in `read_page` output.
- Slice 2 GREEN: the same test passes with sensitive-value redaction, reverse
  ref reuse, the 10,000-element cap, and line-boundary truncation; the
  accessibility-tree anchors were updated for the intentional behavior change.
- Slice 3 RED: `node tests/unit/javascript-tool-repl.regression.test.js`
  failed because `chrome://` pages weren't rejected and evaluation used a
  strict `eval` wrapper.
- Slice 3 GREEN: the same test passes with REPL evaluation, the async
  fallback for `return`, internal-page rejection, and both updated schemas.
- Slice 4 RED: `node tests/unit/computer-tool-guards.regression.test.js`
  failed because the zoom-shortcut and scale helpers didn't exist.
- Slice 4 GREEN: the same test passes with scale normalization, the
  full-resolution coordinate frame, zoom-shortcut rejection, and `type`
  validation; the scroll-offset regression now expects the scaled zoom clip.
- Slice 5 RED: `node tests/unit/blocked-navigation-guard.regression.test.js`
  failed because no mid-call navigation guard existed.
- Slice 5 GREEN: the same test passes; guarded tools discard results that end
  on a blocked URL or pending URL, tab-management tools stay exempt, the MCP
  executor avoids a duplicate next-call error, and managed-policy blocks use
  the administrator wording in tool errors and the side-panel notice.
- Slice 6 RED: `node tests/unit/extension-interference-recovery.test.js`
  failed because the recovery block didn't exist.
- Slice 6 GREEN: the same test passes for the kill switch, iframe selection,
  retry backoff, unrelated retry errors, and attach/sendCommand wiring.
  Extension origins are derived explicitly because Node and Chrome disagree on
  `URL.origin` for `chrome-extension:`.
- Slice 7 RED: `node tests/unit/minimized-window-click-guard.test.js` failed
  because the guard block didn't exist.
- Slice 7 GREEN: the same test passes for visible and minimized windows, the
  kill switch, link filtering, grouped background tabs, abort, and click
  wiring.
- Slice 8 RED: `node tests/unit/agent-indicator-phantom-cursor.test.js`
  failed because the indicator had no cursor or stop-delivery handling.
- Slice 8 GREEN: the same test passes for cursor drawing and movement,
  screenshot hiding, removal, trusted-only stop clicks, dropped-stop
  reporting, and shared contract keys for both producers.
- Slice 9 RED: `node tests/unit/offscreen.test.js` failed because mixed-size
  frames were encoded on the first frame's grid.
- Slice 9 GREEN: the same test passes; frames are padded white to the largest
  frame after overlays, and the padded grid respects the existing 50-megapixel
  budget.
- Slice 10 RED: `node tests/unit/browser-batch.test.js` passed its runtime
  cases but failed its wiring assertions because no executor registered
  `browser_batch`; `node tests/unit/browser-tools-options.test.js` failed
  because the options page didn't load the toggle.
- Slice 10 GREEN: both tests pass. The runtime covers ordering, stop on error,
  permission prompts, blocked navigation, tab validation, cancellation,
  exceptions, content conversion, the single-call reminder, and progress. The
  headed E2E passes without page or console errors.
- Slice 11 RED: `node tests/unit/tool-activity-labels.test.js` failed because
  the label module didn't exist.
- Slice 11 GREEN: the same test passes for computer actions, page tools, host
  extraction, truncation, plan states, translations in en-US, zh-CN, and
  zh-TW, and side-panel wiring.
- Slice 12 RED: `node tests/unit/link-safety.test.js` failed because the
  link-safety module didn't exist.
- Slice 12 GREEN: the same test passes for credential detection, the
  400 ms activation delay, visibility re-arming, dialog wiring, packaging,
  and translations.
- Slice 13 decision: the source's local-time hint is dormant. Its memoized
  component is never assigned or rendered and its regex results are
  discarded, so the matrix records it as excluded instead of shipping
  unreleased behavior.
- Slice 14: the matrix test now fails while any group is `missing`; the
  manifest version is `1.0.94.0` (the release workflow requires four
  segments), and `node scripts/check-release-version.js --current 1.0.94.0
  --previous 1.0.79.6` passes.
- Final validation: `npm run validate:full` passed syntax, docs,
  architecture, manifest, Mermaid vendor, release package, 79 unit and
  integration files, and the headed E2E without page or console errors.
- Runtime inspection: version `1.0.94.0`, unchanged permissions and host
  permissions, no externally connectable origins, and managed key
  `blockedUrlPatterns` only.
- Packaged runtime: `scripts/build-release-import.ps1` produced a 59-item,
  191-file package. The E2E against that package failed once on an
  empty-errors assertion whose details weren't captured, then passed six
  consecutive runs, three of them with error logging enabled.
- Known limitation: Chat Completions providers receive tool-result screenshots
  only as metadata. This predates the change and affects single screenshots
  and batches alike.
- Out of repository scope: MCP clients see tools from the native host, so
  advertising `browser_batch` to them requires a native-host update.
