# Upstream 1.0.94 feature recovery execution plan

This plan implements the
[upstream 1.0.94 recovery specification](../../product-specs/upstream-1.0.94-recovery.md)
as test-driven semantic ports.

## Goal

Recover the accepted provider-independent 1.0.94 behavior without regressing
Claw in Chrome's current behavior, readable recovery architecture, security
controls, or release packaging.

## Constraints

- Treat the supplied 1.0.94 package as read-only source evidence.
- Don't copy the source package, replace generated bundles, or change manifest
  permissions or the content security policy.
- Write one focused failing test before each implementation slice.
- Prefer readable modules; add a semantic anchor test and a recovery-model
  note for every generated bundle patch.
- Keep each slice independently revertible and commit coherent GREEN
  checkpoints on `feat/upstream-1.0.94`.
- Run `npm run validate:fast` before each checkpoint and
  `npm run validate:full` for the final result.

## Baseline and approval gate

Planning started on `main` at `2ba7c16` with a clean working tree. The user
approved the scope, the enabled-by-default batch setting with an options
toggle, truncated oversized `read_page` output, per-slice commits, a final
version change to `1.0.94`, and automatic push.

## Execution slices

1. Behavior matrix: record source identity, accepted groups, owners, and test
   targets in `scripts/upstream-1.0.94-matrix.js`.
2. `read_page` hardening in the accessibility-tree content script.
3. `javascript_tool` REPL semantics and internal-page rejection.
4. `computer` screenshot scale, page-zoom shortcut rejection, and `type`
   validation.
5. Mid-call blocked-navigation detection and managed-policy wording.
6. Foreign-extension debugger interference recovery.
7. Minimized-window click guard.
8. Phantom cursor, trusted stop clicks, and stop-delivery feedback.
9. GIF mixed-size frame padding.
10. `browser_batch` runtime, registration, result conversion, progress UI, and
    options toggle.
11. Tool activity labels in side-panel tool rows.
12. External-link safety warnings.
13. Markdown local-time hint.
14. Version `1.0.94.0`, documentation, full validation, runtime inspection,
    and push.

## Harness checklist

- [ ] The behavior matrix has no `missing` group.
- [ ] Every implemented group has RED and GREEN evidence below.
- [ ] Every generated bundle patch has a semantic anchor test.
- [ ] New strings pass the i18n key parity test in every locale.
- [ ] `docs/recovery-model.md`, `docs/SECURITY.md`, `docs/RELIABILITY.md`, and
  `docs/QUALITY_SCORE.md` describe the final behavior.
- [ ] `npm run validate:fast` passes.
- [ ] `npm run validate:full` passes without page or console errors.
- [ ] `npm run inspect:runtime` shows an unchanged permission set.
- [ ] Commits are pushed to `origin/feat/upstream-1.0.94`.

## Progress evidence

- Baseline: `npm run validate:fast` passed with 66 unit and integration test
  files before any change.
- Slice 2 RED: `node tests/unit/accessibility-tree-hardening.test.js` failed
  because a payment-card value appeared in `read_page` output.
- Slice 2 GREEN: the same test passes with sensitive-value redaction, reverse
  ref reuse, the 10,000-element cap, and line-boundary truncation; the
  accessibility-tree anchors were updated for the intentional behavior change.
- Slice 3 RED: `node tests/unit/javascript-tool-repl.regression.test.js`
  failed because `chrome://` pages weren't rejected and evaluation used a
  strict `eval` wrapper.
- Slice 3 GREEN: the same test passes with REPL evaluation, the async
  fallback for `return`, internal-page rejection, and both updated schemas.
- Slice 4 RED: `node tests/unit/computer-tool-guards.regression.test.js`
  failed because the zoom-shortcut and scale helpers didn't exist.
- Slice 4 GREEN: the same test passes with scale normalization, the
  full-resolution coordinate frame, zoom-shortcut rejection, and `type`
  validation; the scroll-offset regression now expects the scaled zoom clip.
